Lektion 3.5 — Teil 3: Asynchron, Browser & Daten

Prisma ORM

Node.js ca. 90 min Backend

Lernziele

  • Erklären, was ein ORM ist und warum man Prisma verwendet
  • Prisma in einem Node.js-Projekt installieren und initialisieren
  • Datenquelle, Generator und Modelle in schema.prisma definieren
  • Den Prisma Client generieren und CRUD-Operationen ausführen
  • Migrationen erstellen, ein Schema aus einer bestehenden Datenbank ableiten und Umbenennungen ohne Datenverlust durchführen

1 — Einleitung

  • Prisma ist ein JavaScript/TypeScript-basiertes ORM.
  • ORM = Object Relational Mapping – Tabellen der Datenbank werden als Objekte im Code abgebildet.
  • Ziel: mit Objekten arbeiten, statt SQL-Strings manuell zusammenzubauen.
  • Prisma trennt Schema, Migrationen und Laufzeitzugriff klar.

Warum Prisma?

  • Typsichere API (besonders stark mit TypeScript)
  • Klarer Workflow: Schema → Migration → Client
  • Gute Lesbarkeit bei CRUD-Operationen
  • Unterstützt mehrere Datenbanken (z. B. SQLite, PostgreSQL, MySQL)
ℹ
Wo läuft das?

Prisma läuft nicht im Browser, sondern in Node.js – also auf dem Server (siehe Lektion 1.1: Node.js und npm). Der Browser greift über fetch auf eine API zu, die ihrerseits mit Prisma auf die Datenbank zugreift.

2 — Installation und Setup

Terminal Bash 
npm i prisma @prisma/client
npx prisma init
  • prisma: CLI für Schema, Migrationen und Generatoren
  • @prisma/client: Laufzeitbibliothek für den Zugriff im Code
  • Praktisch: Alias prisma='npx prisma'
  • VS-Code-Extension: Prisma (Syntax-Highlighting + IntelliSense)

3 — Prisma Schema: zentrale Steuerung

Im Ordner prisma liegt die Datei schema.prisma.

prisma/schema.prisma Prisma 
datasource db {
  provider = "sqlite"
  url      = "file:./Test.db"
}

generator client {
  provider = "prisma-client-js"
}
  • datasource: Verbindung zur Datenbank
  • generator: welcher Client erzeugt werden soll

Modelle im Schema definieren

prisma/schema.prisma Prisma 
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String?
  createdAt DateTime @default(now())
}
  • model beschreibt eine Tabellenstruktur.
  • Felder, Datentypen und Constraints stehen zentral im Schema (? = optional, @id = Primärschlüssel, @unique = eindeutig).
  • Daraus werden Migrationen und die Client-API abgeleitet.

4 — Client generieren und CRUD

Terminal Bash 
npx prisma generate
app.js JavaScript 
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();
  • Die Klasse PrismaClient wird aus dem Schema erzeugt.
  • Über prisma erfolgen später alle CRUD-Operationen.

CRUD mit dem Prisma Client

app.js JavaScript 
// Create
await prisma.user.create({
  data: { email: 'anna@example.com', name: 'Anna' }
});

// Read
const users = await prisma.user.findMany();

// Update
await prisma.user.update({
  where: { email: 'anna@example.com' },
  data: { name: 'Anna M.' }
});

// Delete
await prisma.user.delete({
  where: { email: 'anna@example.com' }
});
💡
Alles ist asynchron

Jede Prisma-Abfrage liefert ein Promise – deshalb await (Lektion 3.1). Der Code muss in einer async-Funktion stehen.

5 — Schema und Migrationen

Schema aus bestehender Datenbank ableiten

Terminal Bash 
npx prisma db pull
  • Liest eine vorhandene Datenbankstruktur ein (Introspection).
  • Aktualisiert schema.prisma auf Basis der bestehenden Tabellen.
  • Nützlich bei Legacy-Datenbanken oder Fremdprojekten.

Normale Migrationen

Terminal Bash 
# 1) schema.prisma anpassen
npx prisma validate
npx prisma migrate dev
  • Prisma erstellt Migrationen aus Schema-Änderungen.
  • Die Migration wird lokal angewendet.
  • Entwicklungsdatenbank und Schema bleiben synchron.

6 — Umbenennen ohne Datenverlust

Das Problem

  • Umbenennungen (Tabelle/Spalte) erkennt Prisma nicht immer als Rename.
  • Eine naive Migration kann zu DROP + CREATE führen.
  • Folge: möglicher Datenverlust.

Deshalb bei Rename-Änderungen bewusst vorgehen.

Vorgehen

  1. schema.prisma editieren (Rename)
  2. npx prisma validate
  3. Backup (z. B. SQLite-Dump)
  4. npx prisma migrate dev --create-only
  5. SQL-Migration manuell anpassen
  6. npx prisma migrate dev ausführen
  7. Daten prüfen

Beispiel für manuell angepasstes SQL

migration.sql SQL 
ALTER TABLE "OldName" RENAME TO "NewName";
ALTER TABLE "MyTable"
  RENAME COLUMN "oldName" TO "newName";
  • Besser als DROP TABLE bzw. DROP COLUMN
  • Erhält bestehende Daten

7 — Best Practices

  • Vor Migrationen immer ein Backup erstellen.
  • Migrationen in Git versionieren.
  • In Teams: klare Reihenfolge beim Ausrollen von Migrationen.
  • Für Produktion: prisma migrate deploy statt migrate dev.
  • Nach db pull und Schema-Änderungen: prisma generate.
💡
Merke
  • Prisma verbindet Datenmodell, Migration und Datenzugriff in einem Workflow.
  • schema.prisma ist die zentrale Quelle der Wahrheit.
  • Rename-Migrationen erfordern besondere Sorgfalt.
  • Saubere Migrationen sparen später viel Debugging-Aufwand.

Häufige Fehler

Fehler: Client nach Schema-Änderung nicht neu generiert

Ein neues Feld im Schema ist im Code unbekannt (Unknown argument).

Nach jeder Schema-Änderung npx prisma generate (passiert bei migrate dev automatisch).

Fehler: await vergessen

const users = prisma.user.findMany(); liefert ein Promise statt eines Arrays.

const users = await prisma.user.findMany(); in einer async-Funktion.

Fehler: Rename führt zu Datenverlust

Nach dem Umbenennen einer Spalte sind alle Werte weg.

Migration mit --create-only erstellen und das DROP/ADD durch RENAME COLUMN ersetzen.

Aufgaben

Aufgabe 1 Setup

Legen Sie ein neues Node.js-Projekt an, installieren Sie Prisma und konfigurieren Sie eine SQLite-Datenbank mit dem Modell User aus dieser Lektion. Führen Sie die erste Migration aus.

Aufgabe 2 CRUD-Skript

Schreiben Sie ein Skript, das drei Benutzer anlegt, alle ausgibt, einen umbenennt und einen löscht. Prüfen Sie das Ergebnis mit npx prisma studio.

Aufgabe 3 Neues Modell

Ergänzen Sie ein Modell Todo (id, text, completed mit Default false) und führen Sie eine Migration aus. Legen Sie einige Todos an und lesen Sie nur die offenen (where: { completed: false }).

Bonus Rename ohne Datenverlust

Benennen Sie im Modell Todo das Feld text in title um – nach dem Vorgehen aus Abschnitt 6, sodass die bestehenden Daten erhalten bleiben.
