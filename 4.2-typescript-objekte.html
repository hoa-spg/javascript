Objekttypen & Klassen

TypeScript ca. 90 min Grundlagen

Lernziele

  • Die Form von Objekten mit type und interface beschreiben
  • Optionale und schreibgeschützte Eigenschaften verwenden
  • Interfaces mit extends erweitern
  • Arrays von Objekten und Funktionen mit Objektparametern typisieren
  • Klassen mit typisierten Feldern, private und implements schreiben

1 — Objekttypen

Der Typ eines Objekts beschreibt, welche Eigenschaften es hat und welchen Typ jede davon hat. Mit type (Typ-Alias, Lektion 4.1) gibt man ihm einen Namen:

Objekttyp TypeScript 
type Person = {
  vorname: string;
  alter: number;
};

const anna: Person = { vorname: "Anna", alter: 17 };

const tom: Person = { vorname: "Tom" };
// Fehler: Property 'alter' is missing in type '{ vorname: string; }'

anna.altr = 18;
// Fehler: Property 'altr' does not exist on type 'Person'. Did you mean 'alter'?
ℹ
Weniger Tippfehler

In JavaScript hätte anna.altr = 18 einfach eine neue Eigenschaft angelegt (Lektion 1.4). TypeScript erlaubt nur die Eigenschaften, die im Typ stehen.

2 — Optionale und schreibgeschützte Eigenschaften

? und readonly TypeScript 
type Person = {
  readonly id: number;
  vorname: string;
  alter: number;
  email?: string; // optional
};

const anna: Person = { id: 1, vorname: "Anna", alter: 17 }; // ok ohne email

anna.id = 2;
// Fehler: Cannot assign to 'id' because it is a read-only property.
  • email?: Die Eigenschaft darf fehlen – ihr Typ ist string | undefined (wie beim optionalen Parameter in Lektion 4.1).
  • readonly: Der Wert kann nach dem Erzeugen nicht mehr geändert werden.

3 — interface

Objekttypen kann man auch als Interface schreiben – ohne = und ohne Strichpunkt am Ende:

interface TypeScript 
interface Person {
  vorname: string;
  alter: number;
}

interface Schueler extends Person {
  klasse: string;
}

const lisa: Schueler = { vorname: "Lisa", alter: 16, klasse: "2AHIF" };
  • extends übernimmt alle Eigenschaften von Person und fügt neue hinzu – wie bei Klassen.
  • Anders als in Java beschreibt ein TypeScript-Interface vor allem die Form von Daten, nicht nur Methoden.
💡
type oder interface?

Für Objekte sind beide fast gleichwertig. Faustregel für den Kurs: interface für Objekte, type für alles andere (z. B. Union-Typen wie "rot" | "gelb" | "gruen").

4 — Arrays von Objekten und Funktionen

Person[] TypeScript 
interface Person {
  vorname: string;
  alter: number;
}

const klasse: Person[] = [
  { vorname: "Anna", alter: 17 },
  { vorname: "Tom", alter: 16 },
];

function istVolljaehrig(p: Person): boolean {
  return p.alter >= 18;
}

const namen = klasse.map((p) => p.vorname); // erkannt: string[]
const volljaehrige = klasse.filter(istVolljaehrig);

In map und filter braucht p keine Annotation: TypeScript weiß aus Person[], dass jedes Element eine Person ist.

5 — Klassen

In TypeScript-Klassen müssen alle Felder mit Typ deklariert werden:

Klasse TypeScript 
class Konto {
  inhaber: string;
  private kontostand: number;

  constructor(inhaber: string, startbetrag: number) {
    this.inhaber = inhaber;
    this.kontostand = startbetrag;
  }

  einzahlen(betrag: number): void {
    if (betrag <= 0) {
      throw new Error("Betrag muss positiv sein");
    }
    this.kontostand += betrag;
  }

  getKontostand(): number {
    return this.kontostand;
  }
}

const k = new Konto("Anna", 100);
k.einzahlen(50);
k.kontostand = 1000000;
// Fehler: Property 'kontostand' is private and only accessible within class 'Konto'.
  • private wie in Java: Zugriff nur innerhalb der Klasse. Ohne Angabe ist ein Feld public.
  • Unterschied zu #kontostand aus Lektion 1.4: private prüft nur der Compiler, im erzeugten JavaScript ist das Feld normal zugänglich. # ist auch zur Laufzeit privat.

Interfaces implementieren

Mit implements verspricht eine Klasse, alles zu haben, was ein Interface verlangt – wie in Java:

implements TypeScript 
interface Form {
  flaeche(): number;
}

class Rechteck implements Form {
  breite: number;
  hoehe: number;

  constructor(breite: number, hoehe: number) {
    this.breite = breite;
    this.hoehe = hoehe;
  }

  flaeche(): number {
    return this.breite * this.hoehe;
  }
}

const formen: Form[] = [new Rechteck(2, 3), new Rechteck(1, 1)];

flaeche(): number; im Interface beschreibt eine Methode ohne Parameter, die eine Zahl zurückgibt.

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Property has no initializer

Ein Feld ist deklariert, wird aber im Konstruktor nicht gesetzt: Property 'inhaber' has no initializer and is not definitely assigned in the constructor.

Das Feld im Konstruktor zuweisen, ihm einen Startwert geben (kontostand = 0;) oder es optional machen (email?: string).

Fehler: Optionale Eigenschaft ohne Prüfung verwendet

anna.email.toUpperCase() meldet 'anna.email' is possibly 'undefined'.

Vorher prüfen: if (anna.email !== undefined) { … }

Fehler: Objekt mit zusätzlicher Eigenschaft

const p: Person = { vorname: "Anna", alter: 17, hobby: "Tennis" } meldet Object literal may only specify known properties.

Die Eigenschaft in den Typ aufnehmen oder weglassen.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was meldet TypeScript bei anna.altr = 18, wenn der Typ Person nur alter kennt?

Erklärung: In JavaScript entstünde stillschweigend eine neue Eigenschaft. TypeScript fängt solche Tippfehler beim Schreiben ab.

Frage 2 Was bedeutet email?: string in einem Interface?

Erklärung: Deshalb meldet TypeScript bei anna.email.toUpperCase() „possibly undefined“. Vorher prüfen: if (anna.email !== undefined).

Frage 3 Was bewirkt readonly id: number?

Erklärung: readonly prüft TypeScript beim Übersetzen. Wie alle Typen existiert es zur Laufzeit nicht.

Frage 4 Welche Faustregel gilt im Kurs für interface und type?

Erklärung: Für Objekte sind beide fast gleichwertig. Union-Typen wie "rot" | "gelb" gehen aber nur mit type.

Frage 5 Was verspricht eine Klasse mit class Kreis implements Form?

Erklärung: Wie in Java: implements ist ein Vertrag, extends ist Vererbung.
