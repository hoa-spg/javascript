Generics, DOM & fetch

TypeScript ca. 90 min Aufbau

Lernziele

  • Generische Typen wie Array<T> lesen und eigene generische Funktionen schreiben
  • Die Utility-Typen Partial, Omit und Record einsetzen
  • Asynchrone Funktionen mit Promise<T> typisieren und fetch-Daten einen Typ geben
  • DOM-Elemente typsicher verwenden (null prüfen, HTMLInputElement)
  • TypeScript im Browser einsetzen: übersetzen mit tsc oder mit Vite

1 — Generics

Manche Typen brauchen einen weiteren Typ als „Parameter“. Ein Array ist erst vollständig beschrieben, wenn man weiß, wovon es ein Array ist. Diesen Typ-Parameter schreibt man in spitze Klammern – wie bei ArrayList<String> in Java:

Array<T> TypeScript 
const noten: Array<number> = [1, 2, 3]; // dasselbe wie number[]

Auch eigene Funktionen können generisch sein. <T> nach dem Funktionsnamen führt einen Platzhalter für einen Typ ein, der erst beim Aufruf feststeht:

Generische Funktion TypeScript 
function letztes<T>(liste: T[]): T | undefined {
  return liste[liste.length - 1];
}

const n = letztes([1, 2, 3]);      // T = number, n: number | undefined
const s = letztes(["a", "b"]);     // T = string, s: string | undefined
const x = letztes<string>([1, 2]);
// Fehler: Type 'number' is not assignable to type 'string'.
  • Meist erkennt TypeScript T selbst aus dem Argument (Inferenz).
  • Man kann T auch ausdrücklich angeben: letztes<string>(…).
  • Das Ergebnis ist T | undefined, weil ein leeres Array kein letztes Element hat.

2 — Utility-Typen

TypeScript bringt generische Typen mit, die aus einem bestehenden Typ einen neuen bauen:

Partial, Omit, Record TypeScript 
interface Todo {
  id: number;
  text: string;
  completed: boolean;
}

// Partial<T>: alle Eigenschaften optional – z. B. für Änderungen
const aenderung: Partial<Todo> = { completed: true };

// Omit<T, "…">: ohne die genannten Eigenschaften – z. B. vor dem Speichern, wenn die id fehlt
const neu: Omit<Todo, "id"> = { text: "TS lernen", completed: false };

// Record<K, V>: Objekt mit Schlüsseln vom Typ K und Werten vom Typ V
const punkte: Record<string, number> = { anna: 12, tom: 9 };
punkte.lisa = 15; // ok

3 — async-Funktionen und fetch

Eine async-Funktion liefert immer ein Promise (Lektion 3.1). Ihr Rückgabetyp ist deshalb Promise<T> – ein Promise, das einen Wert vom Typ T liefert:

Promise<T> TypeScript 
async function ladeAnzahl(): Promise<number> {
  return 42;
}

response.json() weiß nicht, was der Server schickt, und liefert any. Mit as (Typzusicherung) sagt man TypeScript, welchen Typ die Daten haben:

fetch mit Typ TypeScript 
interface Todo {
  id: number;
  title: string;
  completed: boolean;
}

async function ladeTodo(id: number): Promise<Todo> {
  const response = await fetch("https://jsonplaceholder.typicode.com/todos/" + id);
  if (!response.ok) {
    throw new Error("HTTP-Fehler: " + response.status);
  }
  return (await response.json()) as Todo;
}

async function zeigeTodo(): Promise<void> {
  const todo = await ladeTodo(1);
  console.log(todo.title);  // Editor schlägt title, id, completed vor
  console.log(todo.titel);
  // Fehler: Property 'titel' does not exist on type 'Todo'. Did you mean 'title'?
}
⚠
as prüft nichts
as Todo ist ein Versprechen an den Compiler, keine Kontrolle. Schickt der Server etwas anderes, merkt TypeScript das nicht – der Fehler kommt dann zur Laufzeit.

4 — Das DOM mit Typen

Jedes HTML-Element hat einen eigenen Typ, z. B. HTMLElement, HTMLInputElement oder HTMLButtonElement. Die Methoden aus Lektion 2.1 liefern dabei auch null, wenn nichts gefunden wird:

null prüfen TypeScript 
const ausgabe = document.getElementById("ausgabe"); // HTMLElement | null

ausgabe.textContent = "Hallo";
// Fehler: 'ausgabe' is possibly 'null'.

if (ausgabe !== null) {
  ausgabe.textContent = "Hallo"; // ok – null ist ausgeschlossen
}

querySelector ist generisch: In spitzen Klammern gibt man an, welche Art Element man erwartet. Erst dann kennt TypeScript Eigenschaften wie value, die nur Eingabefelder haben:

Eingabefeld TypeScript 
const input = document.querySelector<HTMLInputElement>("#name-input");
const button = document.querySelector<HTMLButtonElement>("#apply-btn");

if (input !== null && button !== null) {
  button.addEventListener("click", () => {
    console.log(input.value.trim());
  });
}
ℹ
Das Ausrufezeichen !

Wer sicher ist, dass ein Element existiert, kann mit ! nach dem Ausdruck null ausschließen: document.getElementById("app")!. Wie as prüft das nichts – fehlt das Element doch, stürzt das Programm ab. Diese Schreibweise begegnet dir im React-Kurs gleich in der ersten Datei.

5 — TypeScript im Browser

Der Browser führt nur JavaScript aus. Zwei Wege:

  • Selbst übersetzen: npx tsc --watch erzeugt aus app.ts laufend app.js; in der HTML-Datei bindet man wie gewohnt <script src="app.js" defer></script> ein.
  • Mit einem Build-Tool wie Vite: Es übersetzt automatisch und lädt die Seite beim Speichern neu.
Terminal Bash 
npm create vite@latest meine-app -- --template vanilla-ts
cd meine-app
npm install
npm run dev

Vite legt ein fertiges Projekt mit index.html, src/main.ts und tsconfig.json an. Im React-Kurs startet jedes Projekt auf diese Weise – dort mit der Vorlage react-ts.

Häufige Fehler

3 Fehler · zum Aufklappen klicken
Fehler: Property 'value' does not exist on type 'HTMLElement'

document.getElementById("name").value – TypeScript weiß nur, dass es irgendein Element ist.

document.querySelector<HTMLInputElement>("#name") verwenden und auf null prüfen.

Fehler: Rückgabetyp einer async-Funktion ohne Promise

async function lade(): Todo meldet The return type of an async function must be the global Promise<T> type.

async function lade(): Promise<Todo>

Fehler: Mit as Fehler verstecken

const zahl = ("5" as any) as number lässt sich übersetzen, ist zur Laufzeit aber immer noch ein String.

as nur für Daten von außen (z. B. fetch) verwenden; Werte im eigenen Code richtig umwandeln (Number("5")).

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was bedeutet <T> in function erstes<T>(liste: T[]): T?

Erklärung: Mit einem number[] liefert die Funktion eine number, mit einem string[] einen string – ohne Typinformation zu verlieren.

Frage 2 Welchen Rückgabetyp hat async function lade(), die ein Todo liefert?

Erklärung: Eine async-Funktion liefert immer ein Promise. : Todo führt zum Fehler „must be the global Promise<T> type“.

Frage 3 Was prüft const todo = await response.json() as Todo;?

Erklärung: Schickt der Server etwas anderes, merkt TypeScript das nicht – der Fehler kommt dann zur Laufzeit.

Frage 4 Wie greift man typsicher auf den Wert eines Eingabefelds zu?

Erklärung: getElementById liefert nur ein allgemeines HTMLElement (ohne value) oder null.

Frage 5 Was erzeugt Partial<Todo>?

Erklärung: Praktisch z. B. für Updates, bei denen nur einzelne Felder geändert werden. Eine Eigenschaft weglassen würde man mit Omit<Todo, "id">.
