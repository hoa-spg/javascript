Lektion 2.2 — Teil 2: DOM & WebApps

Struktur einfacher WebApps

JavaScript ca. 2 × 90 min Browser

Lernziele

  • Eine Web-App in acht klar getrennte Bausteine gliedern
  • Den Grundsatz „der Zustand steuert die Oberfläche“ verstehen
  • State, Mutatoren, DOM-Referenzen, Erzeugungs- und Render-Funktionen schreiben
  • Event-Handler nach dem Schema on<Event> anlegen und binden
  • Eine vollständige Todo-App nach diesem Muster nachvollziehen

1 — Einleitung

  • Diese Lektion zeigt den strukturierten Aufbau einer einfachen Webanwendung am Beispiel einer Todo-App.
  • Die Anwendung wird in acht Bausteine zerlegt: Zustand, Zustandszugriff, DOM-Referenzen, DOM-Erzeugung, Rendering, Event-Handling, Bindings und Initialisierung.
  • Ziel ist ein klarer Ablauf: Benutzerinteraktion → Zustandsänderung → Neurendern der Oberfläche.
  • Die folgenden Abschnitte zeigen dazu den konkreten JavaScript-Code pro Baustein.

2 — Struktur einfacher WebApps

#BausteinAufgabe
1Application State
Anwendungszustand		Enthält den Zustand der Anwendung – die zentrale Quelle der Wahrheit.
2State Accessors/MutatorsFunktionen zum Lesen und Ändern des Zustands; hier zum Hinzufügen, Umschalten und Löschen von Todos.
3DOM Node ReferencesStatische Referenzen auf DOM-Knoten, die nach dem Start benötigt werden.
4DOM Node Creation FunctionsDynamische Erzeugung von DOM-Knoten bei Benutzerinteraktionen; hier für ein Todo-Listenelement.
5Render FunctionsRendern den Zustand ins DOM; einfaches vollständiges Neurendern beider Listen. Der Zustand steuert die UI: Jede Zustandsänderung löst ein Neurendern aus.
6Event HandlersBehandeln Benutzerinteraktionen (Klick/Änderung), rufen State-Mutatoren auf und rendern danach. Namenskonvention: on<Event>.
7Initialization of BindingsInitiales Verbinden der Event-Handler.
8Initial RenderingInitialer Aufruf von render(), um den Startzustand anzuzeigen.
ℹ
Warum so viel Struktur?

Der Trick ist die Trennung: Event-Handler verändern nie direkt das DOM, sondern nur den Zustand – danach zeichnet render() die Oberfläche neu. Genau dieses Prinzip steckt auch in React und anderen Frameworks.

4 — Die acht Bausteine im Code

1) Application State

Der Anwendungszustand enthält die Daten der App und ist die zentrale Quelle der Wahrheit.

app.js JavaScript 
const state = {
  todos: [
    { text: 'CABS lernen', completed: false },
    { text: 'NSCS lernen', completed: true },
    { text: 'POS/Theorie lernen', completed: false },
    { text: 'WMC programmieren', completed: false },
  ],
};

2) State Accessors/Mutators

Diese Funktionen lesen und ändern den Zustand; hier werden Todos hinzugefügt, umgeschaltet und gelöscht.

app.js JavaScript 
function addNewTodoItemToState(text) {
  state.todos.push({ text: text, completed: false });
}

function toggleTodoState(todoObject) {
  todoObject.completed = !todoObject.completed;
}

function deleteTodoObjectFromState(todoObject) {
  let idx = state.todos.indexOf(todoObject);
  if (idx !== -1) {
    state.todos.splice(idx, 1);
  }
}

3) DOM Node References

Statische Referenzen auf DOM-Knoten, die nach dem Start der Anwendung mehrfach benötigt werden.

app.js JavaScript 
const todoList = document.getElementById('todo-list');
const todoListDone = document.getElementById('todo-list-done');
const addBtn = document.getElementById('todo-add');
const newTodoText = document.getElementById('todo-input');

4) DOM Node Creation Functions

DOM-Knoten werden dynamisch erzeugt; hier wird ein Todo-Listenelement gebaut.

app.js JavaScript 
function createTodoElement(todo) {
  const listItem = document.createElement('li');
  listItem.textContent = todo.text;

  const cb = document.createElement('input');
  cb.type = 'checkbox';
  cb.checked = todo.completed;
  cb.addEventListener('change', (event) => onTodoStateChanged(todo));

  const delBtn = document.createElement('button');
  delBtn.textContent = 'delete';
  delBtn.addEventListener('click', (event) => onTodoObjectDelete(todo));

  listItem.prepend(cb);
  listItem.append(delBtn);
  return listItem;
}

5) Render Functions

Render-Funktionen übertragen den Zustand ins DOM. Hier wird einfach vollständig neu gerendert; jede Zustandsänderung löst ein Re-Render aus.

app.js JavaScript 
function render() {
  todoList.innerHTML = '';
  todoListDone.innerHTML = '';

  for (let todoItem of state.todos) {
    const li = createTodoElement(todoItem);
    if (todoItem.completed) {
      todoListDone.appendChild(li);
    } else {
      todoList.appendChild(li);
    }
  }
}
ℹ
Ergänzt gegenüber den Folien

Auf den Folien ist nur das Rendern der „Done“-Liste abgebildet. Hier steht die vollständige Funktion, die beide Listen leert und jedes Todo der passenden Liste zuordnet.

6) Event Handlers

Event-Handler verarbeiten Benutzeraktionen, rufen State-Mutatoren auf und rendern anschließend neu (Namensschema: on<Event>).

app.js JavaScript 
function onAddBtnPressed() {
  addNewTodoItemToState(newTodoText.value);
  render();
}

function onTodoStateChanged(todoObject) {
  toggleTodoState(todoObject);
  render();
}

function onTodoObjectDelete(todoObject) {
  deleteTodoObjectFromState(todoObject);
  render();
}

7) Initialization of Bindings

Hier werden die Event-Handler initial mit den DOM-Elementen verbunden.

app.js JavaScript 
addBtn.addEventListener('click', (event) => onAddBtnPressed());

8) Initial Rendering

Zum Start wird render() einmal aufgerufen, um den Anfangszustand anzuzeigen.

app.js JavaScript 
render();
