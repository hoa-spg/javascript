Lektion 3.4 — Teil 3: Asynchron, Browser & Daten

Cookies

JavaScript ca. 45 min Browser

Lernziele

  • Erklären, was Cookies sind und was typischerweise darin gespeichert wird
  • First-Party- und Third-Party-Cookies unterscheiden und Tracking verstehen
  • Cookies mit JavaScript setzen, lesen und löschen
  • Die wichtigsten Cookie-Attribute (Max-Age, Path, Secure, HttpOnly, SameSite) kennen
  • Sicherheits- und Datenschutzaspekte (DSGVO) beachten

1 — Was sind Cookies?

  • Kleine Textinformationen, die im Browser gespeichert werden
  • Werden bei passenden Requests automatisch an den Server gesendet
  • Typische Einsätze:
    • Session-ID (Login)
    • Spracheinstellungen
    • Consent-Status (Cookie-Banner)
  • Keine großen Datenmengen speichern (ca. 4 KB pro Cookie)

Was wird üblicherweise in Cookies gespeichert?

Session-Informationenz. B. Session-ID nach dem Login
PräferenzenSprache, Theme, Cookie-Consent-Status
Warenkorb-/Flow-Infosz. B. letzter Schritt im Checkout
Tracking-IDpseudonyme Kennung zur Wiedererkennung
⚠
Wichtig

Keine Passwörter oder sensiblen Klartextdaten speichern. Oft steht nur eine ID im Cookie; die eigentlichen Daten liegen am Server.

2 — First-Party vs. Third-Party Cookies

ArtGesetzt vonBeispiel
First-Party-Cookieder aktuell besuchten Domainshop.example setzt ein Login-/Warenkorb-Cookie
Third-Party-Cookieeiner eingebundenen fremden DomainWerbe-/Analyse-Skript von tracker.example

Third-Party-Cookies werden in modernen Browsern stark eingeschränkt.

Tracking mit Cookies (vereinfacht)

  1. Der Browser lädt Seite A mit eingebundenem Tracker-Skript.
  2. Der Tracker setzt ein Cookie mit eindeutiger ID.
  3. Der Nutzer besucht Seite B mit demselben Tracker.
  4. Die Cookie-ID wird wieder mitgesendet → Wiedererkennung.
  • Ergebnis: Profilbildung über mehrere Seiten möglich.
  • Datenschutzproblem: seitenübergreifendes Verhalten wird verknüpfbar.
  • Daher: Consent, Transparenz und Datenminimierung sind wichtig.

3 — Cookies mit JavaScript

Setzen und lesen

document.cookie JavaScript 
// Cookie setzen (gültig 7 Tage)
document.cookie =
  "theme=dark; Max-Age=604800; Path=/";

// Alle Cookies als ein String
console.log(document.cookie);
  • document.cookie liefert einen String mit allen sichtbaren Cookies.
  • Format: name=value; name2=value2; ...
  • JavaScript kann nur Cookies ohne HttpOnly lesen.
  • Eine Zuweisung an document.cookie setzt bzw. ändert ein Cookie – die anderen bleiben erhalten.

Ein Cookie auslesen

getCookie JavaScript 
function getCookie(name) {
  const parts = document.cookie.split('; ');
  for (const p of parts) {
    const [key, value] = p.split('=');
    if (key === name) return decodeURIComponent(value);
  }
  return null;
}

const theme = getCookie('theme');

Cookie löschen

Löschen durch Max-Age=0 JavaScript 
document.cookie = "theme=; Max-Age=0; Path=/";
  • Name und Path (ggf. Domain) müssen zum Original passen.
  • Sonst bleibt das Cookie erhalten.

4 — Wichtige Cookie-Attribute

AttributBedeutung
Expires oder Max-AgeAblaufzeit (ohne Angabe: Session-Cookie bis zum Schließen des Browsers)
Path, DomainWo das Cookie gilt
SecureNur über HTTPS senden
HttpOnlyNicht durch JavaScript lesbar (nur Server)
SameSiteSchutz gegen CSRF (Lax, Strict, None)

Der Server setzt Cookies über einen Response-Header:

HTTP-Response HTTP 
Set-Cookie: sid=abc123; Path=/; Secure; HttpOnly; SameSite=Lax

5 — Sicherheit und Datenschutz

  • Keine sensiblen Daten im Klartext in Cookies speichern.
  • Session-Cookies: Secure + HttpOnly + SameSite verwenden.
  • Cookies sind pro Domain/Path begrenzt und werden bei Requests mitgeschickt.
  • In der EU: nicht notwendige Cookies erst nach Einwilligung (DSGVO).
💡
Merke
  • Cookies eignen sich für kleine, request-relevante Daten.
  • Für reine Frontend-Daten ist localStorage oft einfacher (Lektion 3.3).
  • Sicherheitsattribute sind bei Login-Cookies Pflicht.

Häufige Fehler

Fehler: Cookie lässt sich nicht löschen

document.cookie = "theme=; Max-Age=0" wirkt nicht, weil das Cookie mit Path=/ gesetzt wurde.

Beim Löschen exakt denselben Path (und ggf. Domain) angeben.

Fehler: document.cookie als Objekt behandeln

document.cookie.theme ist undefined.

document.cookie ist ein String – mit einer Funktion wie getCookie zerlegen.

Fehler: Sonderzeichen im Wert

Werte mit ;, = oder Leerzeichen zerbrechen das Cookie-Format.

Beim Setzen encodeURIComponent(wert), beim Lesen decodeURIComponent.

Aufgaben

Aufgabe 1 Cookies untersuchen

Öffnen Sie eine Nachrichtenseite und untersuchen Sie in den Entwicklertools (Tab Application bzw. Storage → Cookies), welche Cookies gesetzt werden. Welche sind First-Party, welche Third-Party? Welche haben HttpOnly?

Aufgabe 2 Sprache merken

Zwei Buttons „Deutsch“ und „English“ setzen ein Cookie lang (gültig 30 Tage). Beim Laden der Seite wird die Begrüßung in der gespeicherten Sprache angezeigt.

Aufgabe 3 Cookie-Banner

Bauen Sie einen einfachen Cookie-Banner mit „Akzeptieren“ und „Ablehnen“. Die Entscheidung wird in einem Cookie consent gespeichert; ist es vorhanden, erscheint der Banner nicht mehr.

Bonus setCookie und deleteCookie

Schreiben Sie zu getCookie passende Funktionen setCookie(name, value, days) und deleteCookie(name) – inklusive encodeURIComponent.
