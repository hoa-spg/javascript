Lektion 3.2 — Teil 3: Asynchron, Browser & Daten

Event Loop

JavaScript ca. 45 min Asynchron

Lernziele

  • Erklären, wie single-threaded JavaScript trotzdem asynchron arbeiten kann
  • Call Stack, Web APIs, Task Queue und Microtask Queue unterscheiden
  • Die Ausgabereihenfolge von synchronem Code, Promises und Timern vorhersagen
  • Blockierenden Code erkennen und vermeiden

1 — Event Loop: Grundidee

  • JavaScript führt Code im Browser bzw. in Node.js grundsätzlich single-threaded aus – es läuft immer nur eine Sache gleichzeitig.
  • Der Event Loop ermöglicht trotzdem asynchrones Verhalten (Timer, Netzwerk, Benutzerereignisse).
  • Ablauf: Der Stack wird abgearbeitet, dann werden wartende Aufgaben aus Queues eingeplant.
  • Ziel: Die Oberfläche bleibt reaktionsfähig, obwohl asynchrone Aufgaben im Hintergrund laufen.

2 — Bausteine des Event Loops

BausteinAufgabe
Call StackFührt die aktuell laufenden Funktionsaufrufe aus.
Web APIs / Runtime APIsBearbeiten Timer, I/O und Events außerhalb des Stacks.
Task Queue (Macrotasks)z. B. setTimeout, DOM-Events
Microtask Queuez. B. Promise-then/catch, queueMicrotask
ℹ
Regel

Nach jedem Durchlauf des Stacks werden zuerst alle Microtasks abgearbeitet – erst danach kommt die nächste Macrotask an die Reihe.

3 — Beispiel: Reihenfolge der Ausgabe

Reihenfolge JavaScript 
console.log('A');

setTimeout(() => {
  console.log('B (macrotask)');
}, 0);

Promise.resolve().then(() => {
  console.log('C (microtask)');
});

console.log('D');
  • Ausgabe: A, D, C, B
  • Grund: Erst der synchrone Code, dann die Microtasks, dann die Macrotasks – auch bei setTimeout(…, 0).

4 — Praxis: Blockierenden Code vermeiden

Blockierender Code JavaScript 
function heavyWork(ms) {
  const start = Date.now();
  while (Date.now() - start < ms) {
    // blockiert den Thread
  }
}

console.log('Start');
setTimeout(() => console.log('Timer fertig'), 0);
heavyWork(2000);
console.log('Ende');
  • Solange heavyWork läuft, kann der Event Loop nichts anderes ausführen.
  • Konsequenz: Timer, Klicks und Rendering werden verzögert – die Seite „friert ein“.
  • Lösung: Arbeit aufteilen, asynchron planen oder in einen Web Worker auslagern.

Häufige Fehler

Fehler: setTimeout(…, 0) läuft „sofort“

Der Code im Timer wird erst ausgeführt, wenn der Stack leer ist und alle Microtasks erledigt sind.

0 ms bedeutet „so bald wie möglich“, nicht „jetzt“.

Fehler: Ergebnis außerhalb des Callbacks verwenden

let daten; fetch(url).then(r => daten = r); – direkt danach ist daten noch undefined.

Mit dem Ergebnis innerhalb von then bzw. nach await weiterarbeiten.

Fehler: Lange Schleifen im Event-Handler

Ein Klick löst eine rechenintensive Schleife aus, und die Seite reagiert sekundenlang nicht.

Arbeit in kleinere Stücke teilen (z. B. mit setTimeout) oder einen Web Worker verwenden.
