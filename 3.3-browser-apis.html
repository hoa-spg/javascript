Lektion 3.3 — Teil 3: Asynchron, Browser & Daten

Browser APIs

JavaScript ca. 90 min Browser

Lernziele

  • Die wichtigsten Browser APIs kennen
  • Daten mit der Fetch API laden und senden – inklusive Fehlerbehandlung
  • Verstehen, was CORS ist und wie CORS-Fehler wirklich behoben werden
  • Daten mit localStorage und sessionStorage speichern
  • Standort mit der Geolocation API abfragen
  • Query-Parameter mit der URL-API lesen und die URL mit der History API ändern

1 — Überblick: Wichtige Browser APIs

  • Der Browser stellt viele APIs direkt in JavaScript bereit.
  • Häufig gebraucht im Alltag:
    • Fetch API (HTTP-Requests)
    • Web Storage API (localStorage, sessionStorage)
    • Geolocation API (Standort)
    • URL / History API (Navigation, Query-Parameter)
  • Fast alle APIs sind asynchron oder eventbasiert.

2 — Fetch API

Daten vom Server laden

GET JavaScript 
async function loadUsers() {
  const response = await fetch('/api/users');
  const users = await response.json();
  console.log(users);
}
  • fetch(url) liefert ein Promise.
  • Antwortdaten kommen häufig als JSON: response.json()
  • Standard für REST-APIs im Browser

Daten senden und Fehler behandeln

POST JavaScript 
async function saveTodo(todo) {
  try {
    const res = await fetch('/api/todos', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(todo)
    });
    if (!res.ok) throw new Error('HTTP ' + res.status);
  } catch (err) {
    console.error('Speichern fehlgeschlagen:', err.message);
  }
}

3 — CORS kurz erklärt

  • CORS = Cross-Origin Resource Sharing
  • Browser-Schutzmechanismus für Requests von Origin A nach Origin B
  • Origin = Schema + Host + Port
  • Bei einem Cross-Origin-Fetch entscheidet der Server über Header, ob der Zugriff erlaubt ist.

Wichtige Response-Header

Response-Header HTTP 
Access-Control-Allow-Origin: https://meine-app.example
Access-Control-Allow-Origin: *        (nur für öffentliche Daten)

Typische Browser-Fehlermeldung: blocked by CORS policy

CORS-Fehler beheben: Was wirklich hilft

  • Hauptregel: CORS wird serverseitig gelöst, nicht im Frontend.
  • Der API-Server muss passende Header liefern (Origin, Methoden, Header).
  • Bei komplexen Requests sendet der Browser zusätzlich vorab einen OPTIONS-Preflight.
mode JavaScript 
fetch('https://api.example.com/data', {
  method: 'GET',
  mode: 'cors' // Default im Browser
});
  • mode: 'no-cors' macht Antworten meist opaque (praktisch nicht nutzbar).
  • Für die Entwicklung sinnvoll: Dev-Proxy (Vite/Webpack) oder ein eigenes Backend als Proxy.
  • Browser-CORS-Plugins nur als Notlösung für lokale Tests.
ℹ
Zusammenhang mit der Same-Origin-Policy

CORS ist die kontrollierte Ausnahme von der Same-Origin-Policy (siehe HTML-&-CSS-Kurs, Lektion 1.3): Standardmäßig blockiert der Browser Cross-Origin-Antworten – per CORS-Header kann der Server sie freigeben.

4 — Web Storage API

  • localStorage: Daten bleiben dauerhaft gespeichert.
  • sessionStorage: Daten nur, bis Tab/Fenster geschlossen wird.
  • Speichert nur Strings → Objekte mit JSON.stringify / JSON.parse umwandeln.
localStorage JavaScript 
const settings = { darkMode: true, fontSize: 16 };
localStorage.setItem('settings', JSON.stringify(settings));

const raw = localStorage.getItem('settings');
const loaded = raw ? JSON.parse(raw) : null;

5 — Geolocation API

Standort JavaScript 
navigator.geolocation.getCurrentPosition(
  (position) => {
    const lat = position.coords.latitude;
    const lon = position.coords.longitude;
    console.log(lat, lon);
  },
  (error) => console.error(error.message)
);
  • Der Benutzer muss die Standortfreigabe erlauben.
  • Nützlich für Karten, Wetter und ortsbezogene Dienste.

6 — URL- und History-API

URL / History JavaScript 
const url = new URL(window.location.href);
const page = url.searchParams.get('page');

history.pushState({}, '', '?page=2');
  • URLSearchParams (über url.searchParams): Query-Parameter lesen/schreiben
  • history.pushState: URL ändern ohne Seiten-Reload
  • Basis für Single-Page-Apps (Routing)

7 — Zusammenfassung

  • fetch + async/await für die Serverkommunikation
  • localStorage/sessionStorage für kleine, clientseitige Daten
  • Geolocation nur mit Benutzerzustimmung
  • URL/History wichtig für Navigation und Zustand in der URL

Häufige Fehler

Fehler: CORS im Frontend „lösen“ wollen

mode: 'no-cors' oder eigene Request-Header beseitigen die Fehlermeldung nicht bzw. liefern eine unbrauchbare Antwort.

Der Server muss Access-Control-Allow-Origin senden – oder man verwendet einen Proxy.

Fehler: Objekte direkt in localStorage speichern

localStorage.setItem('s', settings) speichert den Text "[object Object]".

Vorher JSON.stringify, beim Lesen JSON.parse.

Fehler: Body-Format nicht angegeben

Der Server erhält beim POST keine Daten oder kann sie nicht lesen.

Header 'Content-Type': 'application/json' setzen und den Body mit JSON.stringify erzeugen.
