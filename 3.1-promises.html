Lektion 3.1 — Teil 3: Asynchron, Browser & Daten

Promises & async/await

JavaScript ca. 90 min Asynchron

Lernziele

  • Das Problem verschachtelter Callbacks („Callback-Hell“) erkennen
  • Die drei Zustände eines Promise kennen und Promises selbst erzeugen
  • Ergebnisse und Fehler mit then, catch und finally verarbeiten
  • Promise-Ketten bilden und verstehen, wie Fehler darin weitergereicht werden
  • Mehrere Promises mit Promise.all und Promise.allSettled koordinieren
  • Daten mit fetch laden – mit then und mit async/await

1 — Einleitung

  • Promises sind ein Mechanismus für asynchrone Operationen in JavaScript.
  • Ein Promise repräsentiert ein zukünftiges Ergebnis: erfolgreich oder fehlgeschlagen.
  • Ziel: besser lesbarer und besser strukturierter asynchroner Code als mit verschachtelten Callbacks.
  • Typische Anwendungsfälle: API-Aufrufe, Datei-/Netzwerkzugriffe, Timer.

2 — Problem ohne Promises (Callback-Hell)

Callback-Hell JavaScript 
setTimeout(() => {
  console.log('Schritt 1');
  setTimeout(() => {
    console.log('Schritt 2');
    setTimeout(() => {
      console.log('Schritt 3');
    }, 500);
  }, 500);
}, 500);
  • Tiefe Verschachtelung macht den Code schwer lesbar.
  • Die Fehlerbehandlung verteilt sich auf viele Stellen.

3 — Grundidee eines Promise

Ein Promise hat drei Zustände:

pendingwartend
fulfillederfolgreich abgeschlossen
rejectedmit Fehler abgelehnt
ℹ
Wichtig

Ein Promise wechselt nur einmal von pending zu fulfilled oder rejected. Danach bleibt der Zustand unverändert.

Promise erzeugen

new Promise JavaScript 
const p = new Promise((resolve, reject) => {
  const ok = true;
  if (ok) {
    resolve('Daten erfolgreich geladen');
  } else {
    reject(new Error('Laden fehlgeschlagen'));
  }
});
  • resolve(wert) markiert das Promise als erfolgreich.
  • reject(fehler) markiert es als fehlgeschlagen.

4 — then(), catch() und finally()

then / catch JavaScript 
p.then((result) => {
    console.log('OK:', result);
  })
  .catch((err) => {
    console.error('Fehler:', err.message);
  });
  • then() verarbeitet den Erfolgsfall.
  • catch() verarbeitet Fehler.
  • Beide geben wieder ein Promise zurück.
finally JavaScript 
function ladeDaten() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(['A', 'B', 'C']), 800);
  });
}

ladeDaten()
  .then((daten) => console.log(daten))
  .catch((err) => console.error(err))
  .finally(() => console.log('Ladevorgang beendet'));
  • finally() läuft immer – egal ob Erfolg oder Fehler.
  • Typisch für Aufräumarbeiten (z. B. Lade-Spinner ausblenden).

5 — Promise-Ketten (Chaining)

Chaining JavaScript 
Promise.resolve(2)
  .then((x) => x * 3)
  .then((x) => x + 1)
  .then((x) => {
    console.log(x); // 7
    return x;
  })
  .catch((err) => console.error(err));
  • Jeder then()-Schritt erhält das Ergebnis des vorherigen Schritts.
  • Rückgabewerte werden automatisch weitergereicht.

Fehler in Ketten

Fehler in Ketten JavaScript 
Promise.resolve('Start')
  .then(() => {
    throw new Error('Etwas ist schiefgelaufen');
  })
  .then(() => {
    console.log('Wird nicht mehr ausgefuehrt');
  })
  .catch((err) => {
    console.log('Gefangen:', err.message);
  });
  • Ein Fehler überspringt die nachfolgenden then()-Blöcke.
  • Der Fehler landet im nächsten passenden catch().

Die Callback-Hell von oben als Kette – flach statt verschachtelt:

Callback-Hell aufgelöst JavaScript 
const warte = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

warte(500)
  .then(() => { console.log('Schritt 1'); return warte(500); })
  .then(() => { console.log('Schritt 2'); return warte(500); })
  .then(() => console.log('Schritt 3'));

6 — Mehrere Promises koordinieren

Promise.all() (parallel, alles muss klappen)

Promise.all JavaScript 
const p1 = Promise.resolve('A');
const p2 = new Promise((resolve) => setTimeout(() => resolve('B'), 300));
const p3 = Promise.resolve('C');

Promise.all([p1, p2, p3])
  .then((werte) => console.log(werte)) // ['A', 'B', 'C']
  .catch((err) => console.error(err));
  • Erfolgreich nur, wenn alle Promises erfolgreich sind.
  • Bei einem Fehler wird sofort abgebrochen.

Promise.allSettled() (alle Ergebnisse sammeln)

Promise.allSettled JavaScript 
const p1 = Promise.resolve('OK');
const p2 = Promise.reject(new Error('Netzwerkfehler'));

Promise.allSettled([p1, p2])
  .then((results) => {
    console.log(results);
    // [
    //   { status: 'fulfilled', value: 'OK' },
    //   { status: 'rejected', reason: Error(...) }
    // ]
  });
  • Wartet auf alle Promises.
  • Praktisch, wenn Teilfehler erlaubt sind.

7 — Praxisbeispiel mit fetch()

fetch mit then JavaScript 
fetch('https://some-url.com/api/1')
  .then((response) => {
    if (!response.ok) {
      throw new Error('HTTP-Fehler: ' + response.status);
    }
    return response.json();
  })
  .then((todo) => {
    console.log('Titel:', todo.title);
  })
  .catch((err) => {
    console.error('Request fehlgeschlagen:', err.message);
  });
⚠
CORS

Wenn im Browser blocked by CORS policy erscheint, siehe Lektion 3.3 (Browser APIs, Abschnitt CORS).

8 — Promises und async/await

  • async/await ist „Syntax-Zucker“ auf Basis von Promises.
  • Die Logik bleibt gleich, der Code wirkt oft linearer und lesbarer.
  • Die Fehlerbehandlung erfolgt mit try/catch.
async / await JavaScript 
async function ladeTodo() {
  try {
    const response = await fetch('https://some-url.com/api/1');
    const todo = await response.json();
    console.log(todo.title);
  } catch (err) {
    console.error(err.message);
  }
}

await wartet, bis das Promise erfüllt ist, und liefert dessen Wert. Es darf nur in Funktionen stehen, die mit async markiert sind – eine async-Funktion gibt selbst immer ein Promise zurück. CORS gilt auch hier bei Browser-Requests mit fetch.

9 — Zusammenfassung

  • Promises strukturieren asynchronen Code klar und robust.
  • then/catch/finally decken Erfolg, Fehler und Aufräumen ab.
  • Mit all und allSettled können mehrere asynchrone Aufgaben koordiniert werden.
  • async/await baut auf Promises auf und vereinfacht die Schreibweise.

Häufige Fehler

Fehler: return in der Kette vergessen

Im then wird response.json() aufgerufen, aber nicht zurückgegeben – der nächste Schritt bekommt undefined.

Promises in der Kette immer mit return weitergeben.

Fehler: await vergessen

const data = response.json(); liefert ein Promise statt der Daten.

const data = await response.json();

Fehler: HTTP-Fehler werden nicht erkannt

fetch wirft bei 404 oder 500 keinen Fehler – nur bei Netzwerkproblemen.

response.ok prüfen und bei Bedarf selbst einen Error werfen.

Aufgaben

Aufgabe 1 warte(ms)

Schreiben Sie eine Funktion warte(ms), die ein Promise zurückgibt, das nach ms Millisekunden erfüllt wird. Geben Sie damit „3“, „2“, „1“, „Los!“ im Sekundenabstand aus – einmal mit then, einmal mit async/await.

Aufgabe 2 Würfeln mit Fehler

Schreiben Sie wuerfle(): ein Promise, das nach 500 ms mit einer Zufallszahl 1–6 erfüllt wird, bei einer 1 aber mit dem Fehler „Pech!“ abgelehnt wird. Behandeln Sie beide Fälle und geben Sie in finally „fertig“ aus.

Aufgabe 3 Daten laden

Laden Sie mit fetch die Daten von https://jsonplaceholder.typicode.com/todos/1 und zeigen Sie den Titel in einem <p> auf der Seite an. Während des Ladens steht dort „lädt …“.

Bonus Parallel laden

Laden Sie die Todos 1 bis 5 parallel mit Promise.all und geben Sie alle Titel als Liste aus. Was passiert, wenn eine der URLs falsch ist? Probieren Sie dasselbe mit Promise.allSettled.
