Lektion 4.1 — Teil 4: TypeScript

TypeScript-Grundlagen

TypeScript ca. 90 min Grundlagen

Lernziele

  • Wissen, was TypeScript ist und welche Fehler es schon beim Schreiben findet
  • Ein TypeScript-Projekt anlegen und mit tsc in JavaScript übersetzen
  • Variablen, Arrays und Funktionen mit Typen versehen
  • Typinferenz nutzen: Typen nur dort angeben, wo sie nötig sind
  • Union-Typen und Literal-Typen einsetzen und mit typeof eingrenzen

1 — Was ist TypeScript?

  • TypeScript (kurz TS) ist JavaScript mit Typen, entwickelt von Microsoft (2012).
  • Jedes JavaScript-Programm ist auch gültiges TypeScript – TS fügt nur Typangaben hinzu.
  • Browser und Node.js verstehen kein TypeScript: Der Compiler tsc prüft die Typen und übersetzt den Code in normales JavaScript. Die Typen fallen dabei weg.
  • Vorteil: Viele Fehler zeigt der Editor schon beim Schreiben an, nicht erst zur Laufzeit.

Ein typischer JavaScript-Fehler, der erst beim Ausführen auffällt:

app.js JavaScript 
function flaeche(breite, hoehe) {
  return breite * hoehe;
}

console.log(flaeche("5", 3));  // 15 – zufällig richtig
console.log(flaeche("fünf", 3)); // NaN – kein Fehler, nur ein falsches Ergebnis

Dieselbe Funktion in TypeScript: Nach dem Parameternamen steht mit Doppelpunkt der Typ.

app.ts TypeScript 
function flaeche(breite: number, hoehe: number): number {
  return breite * hoehe;
}

console.log(flaeche("fünf", 3));
// Fehler: Argument of type 'string' is not assignable to parameter of type 'number'.
ℹ
Vergleich zu Java

Wie in Java gibt es statische Typen – nur steht der Typ nach dem Namen (breite: number statt int breite). Und anders als in Java existieren die Typen nur beim Entwickeln: Im fertigen JavaScript sind sie verschwunden.

2 — Projekt anlegen und übersetzen

Terminal Bash 
npm init -y
npm install --save-dev typescript

--save-dev installiert TypeScript als Entwicklungswerkzeug: Es wird nur zum Übersetzen gebraucht, nicht beim Ausführen. Die Einstellungen des Compilers stehen in der Datei tsconfig.json. Für den Kurs reicht diese:

tsconfig.json JSON 
{
  "compilerOptions": {
    "target": "es2022",
    "strict": true
  }
}
  • target: welche JavaScript-Version erzeugt wird.
  • strict: alle strengen Prüfungen einschalten – immer verwenden.
Terminal Bash 
npx tsc          # übersetzt alle .ts-Dateien im Ordner, z. B. app.ts → app.js
node app.js      # das erzeugte JavaScript ausführen
npx tsc --watch  # übersetzt bei jedem Speichern automatisch neu
💡
VS Code

VS Code kann TypeScript von Haus aus: Fehler werden rot unterstrichen, und wenn man mit der Maus über eine Variable fährt, zeigt der Editor ihren Typ an.

3 — Typen für Variablen

Die Grundtypen heißen wie die Ergebnisse von typeof aus Lektion 1.1:

Typannotationen TypeScript 
let alter: number = 17;
const vorname: string = "Anna";
let fertig: boolean = false;

alter = "achtzehn";
// Fehler: Type 'string' is not assignable to type 'number'.

Die Angabe : number heißt Typannotation. Eine Variable behält ihren Typ – anders als in JavaScript kann aus einer Zahl später kein String werden.

4 — Typinferenz

Meistens muss man den Typ gar nicht hinschreiben: TypeScript erkennt ihn aus dem Startwert.

Typinferenz TypeScript 
let alter = 17;          // TypeScript erkennt: number
const vorname = "Anna";  // string

alter = "achtzehn";
// Fehler: Type 'string' is not assignable to type 'number'.
💡
Faustregel

Typen bei Funktionsparametern immer angeben – dort kann TypeScript sie nicht erraten. Bei Variablen mit Startwert den Typ weglassen und TypeScript arbeiten lassen.

5 — Arrays

Ein Array-Typ besteht aus dem Typ der Elemente und []:

Arrays TypeScript 
const noten: number[] = [1, 2, 2, 3];
const tiere = ["Hund", "Katze"]; // erkannt: string[]

noten.push(4);       // ok
noten.push("gut");
// Fehler: Argument of type 'string' is not assignable to parameter of type 'number'.

Auch Array-Methoden aus Lektion 1.3 kennen die Typen: noten.map((n) => n * 2) liefert wieder ein number[], und n ist automatisch eine number.

6 — Union-Typen und Literal-Typen

Mit | („oder“) erlaubt man mehrere Typen – ein Union-Typ:

Union-Typen TypeScript 
let id: number | string = 42;
id = "A-42"; // auch erlaubt

let gewinner: string | null = null; // noch kein Gewinner
gewinner = "Anna";

Statt eines ganzen Typs kann man auch einzelne erlaubte Werte angeben (Literal-Typen):

Literal-Typen TypeScript 
let ampel: "rot" | "gelb" | "gruen" = "rot";
ampel = "gruen"; // ok
ampel = "blau";
// Fehler: Type '"blau"' is not assignable to type '"rot" | "gelb" | "gruen"'.

Lange Typen gibt man mit type einen Namen (Typ-Alias) und verwendet diesen Namen dann wie einen eingebauten Typ:

Typ-Alias TypeScript 
type Ampelfarbe = "rot" | "gelb" | "gruen";

let ampel: Ampelfarbe = "rot";

7 — Funktionen

Funktionen TypeScript 
function begruesse(vorname: string, anrede?: string): string {
  if (anrede === undefined) {
    return "Hallo " + vorname;
  }
  return anrede + " " + vorname;
}

begruesse("Anna");          // "Hallo Anna"
begruesse("Anna", "Liebe"); // "Liebe Anna"
begruesse();
// Fehler: Expected 1-2 arguments, but got 0.

function log(text: string): void {
  console.log(text);
}

const verdopple = (x: number): number => x * 2;
  • Der Typ nach der Klammer ): string ist der Rückgabetyp. Er kann meist auch weggelassen werden (Inferenz).
  • void: Die Funktion gibt nichts zurück.
  • anrede?: optionaler Parameter. Wird er weggelassen, ist er undefined – sein Typ ist also string | undefined.
  • Anders als in JavaScript (Lektion 1.2) prüft TypeScript die Anzahl der Argumente.

8 — Typen eingrenzen (Narrowing)

Bei einem Union-Typ erlaubt TypeScript nur, was für alle Typen passt. Im Beispiel unten gibt es toFixed(2) (Zahl auf 2 Nachkommastellen runden) nur für Zahlen und toUpperCase() (in Großbuchstaben) nur für Strings. Mit einer Prüfung grenzt man den Typ ein:

Narrowing mit typeof TypeScript 
function formatiere(wert: number | string): string {
  if (typeof wert === "number") {
    return wert.toFixed(2); // hier ist wert sicher eine number
  }
  return wert.toUpperCase(); // hier bleibt nur noch string übrig
}

Ohne die if-Prüfung meldet TypeScript bei beiden Methoden einen Fehler. Genauso funktioniert die Prüfung if (gewinner !== null) bei string | null.

9 — any: die Notbremse

any TypeScript 
let x: any = 5;
x = "Text";
x.gibtEsNicht(); // kein Fehler beim Übersetzen – aber Absturz zur Laufzeit

any schaltet die Typprüfung für diese Variable ab. Damit verliert man den ganzen Nutzen von TypeScript – also nur als Notlösung verwenden.

Häufige Fehler

Fehler: Cannot redeclare block-scoped variable 'name'

Eine Datei ohne Imports wird als globales Script behandelt. Dort gibt es schon Browser-Variablen wie name oder status – eine eigene const name kollidiert damit.

Einen anderen Namen wählen (z. B. vorname) oder ganz ans Ende der Datei export {}; schreiben – dann ist die Datei ein eigenes Modul.

Fehler: Die .js-Datei statt der .ts-Datei bearbeitet

Änderungen in app.js sind nach dem nächsten tsc wieder weg.

Nur die .ts-Datei bearbeiten; die .js-Datei wird erzeugt.

Fehler: Fehler mit any „wegmachen“

Ein rot unterstrichener Ausdruck wird mit : any versehen – der Fehler verschwindet aus dem Editor, aber nicht aus dem Programm.

Die Fehlermeldung lesen und den Typ richtigstellen oder mit einer Prüfung eingrenzen.

Aufgaben

Aufgabe 1 Projekt einrichten

Legen Sie ein Projekt mit tsconfig.json wie in Abschnitt 2 an. Schreiben Sie in app.ts die Funktion flaeche, rufen Sie sie einmal richtig und einmal mit einem String auf. Lesen Sie die Fehlermeldung von npx tsc, entfernen Sie den falschen Aufruf und führen Sie das Ergebnis mit node app.js aus.

Aufgabe 2 Typen ergänzen

Schreiben Sie typisierte Funktionen: durchschnitt(zahlen) für ein number[], istVolljaehrig(alter) mit Rückgabe boolean und wiederhole(text, anzahl?), die den Text anzahl-mal (Standard: 2-mal) aneinanderhängt.

Aufgabe 3 Ampel

Definieren Sie type Ampelfarbe = "rot" | "gelb" | "gruen" und eine Funktion naechsteFarbe(farbe: Ampelfarbe): Ampelfarbe (rot → gruen → gelb → rot). Was meldet TypeScript, wenn Sie in der Funktion einen Fall vergessen und keinen Rückgabewert liefern?

Bonus JavaScript umstellen

Nehmen Sie Ihre Selection-Sort-Lösung aus Lektion 1.1, benennen Sie sie in .ts um und ergänzen Sie alle Typen, bis npx tsc keine Fehler mehr meldet.

Quiz

5 Fragen · zum Aufklappen klicken

Frage 1 Was passiert mit den TypeScript-Typen im fertigen Programm?

Erklärung: tsc prüft die Typen und übersetzt nach JavaScript. Zur Laufzeit gibt es keine Typprüfung.

Frage 2 Wo sollte man Typen immer explizit angeben?

Erklärung: Bei let x = 5 erkennt TypeScript number aus dem Startwert (Typinferenz). Parameter haben keinen Startwert.

Frage 3 Welche Werte darf eine Variable vom Typ "rot" | "gelb" | "gruen" haben?

Erklärung: Das ist ein Union aus Literal-Typen. Mit type Ampel = … bekommt der Typ einen Namen.

Frage 4 Bei wert: number | string meldet TypeScript bei wert.toFixed(2) einen Fehler. Wie löst man das?

Erklärung: Bei einem Union-Typ ist nur erlaubt, was für alle Typen passt. Nach der typeof-Prüfung weiß TypeScript, dass es eine Zahl ist (Narrowing).

Frage 5 Du änderst app.js, aber nach dem nächsten tsc sind die Änderungen weg. Warum?

Erklärung: Die .js-Datei ist ein Ergebnis des Compilers und wird bei jedem Übersetzen überschrieben.
